0001: CNN 基础 — 从图片到特征图

这一课的目标是：能看懂 common.py 里的 nn.Sequential 定义，知道每一行在做什么。不需要数学公式，需要的是直觉。

1. 为什么需要 CNN

一张 256×256 的彩色图片有 256 × 256 × 3 = 196,608 个数字（像素值）。如果用全连接网络，第一个隐藏层每个神经元就要 19 万个权重 — 参数量爆炸，而且完全忽略了"像素之间的距离关系"。

CNN 的解决思路：不看整张图，只看一个小窗口。一个 4×4 的窗口只有 16 个像素，在这个窗口上学习一个 卷积核（kernel），然后把这个窗口从左到右、从上到下滑过整张图。

2. 三个核心操作

2.1 卷积（Convolution）

打开 common.py，看 get_pdn_small 的第一行：

nn.Conv2d(in_channels=3, out_channels=128, kernel_size=4, padding=3)

参数含义：

参数值含义
in_channels3输入是 RGB 三通道彩色图
out_channels128输出 128 个"特征图" — 相当于学了 128 种不同的 4×4 模式检测器
kernel_size4每个检测器的窗口是 4×4 像素
padding3在图片四周各补 3 个像素的边，保证输出尺寸和输入一样大
输入: [1, 3, 256, 256] (batch=1, 3通道, 256×256) │ ▼ Conv2d(3→128, kernel=4, padding=3) │ 输出: [1, 128, 256, 256] (batch=1, 128通道, 大小不变)

直观理解：输入是一张图，输出是 128 张"特征图"。第 37 张特征图可能对"水平边缘"敏感，第 89 张可能对"45°纹理"敏感。每个通道等于一个专门的检测器。

2.2 ReLU — 激活函数

nn.ReLU(inplace=True)

简单到只有一行代码的事：把卷积输出中所有 负数变成 0，正数保持不变。

输入:  [ 0.8, -0.3,  2.1, -1.5,  0.0 ]
输出:  [ 0.8,  0.0,  2.1,  0.0,  0.0 ]

为什么需要：没有 ReLU，多层卷积叠加就等于一个大卷积（线性函数的组合还是线性函数）。ReLU 引入非线性，让网络能学习复杂的视觉模式。

2.3 AvgPool — 平均池化（下采样）

nn.AvgPool2d(kernel_size=2, stride=2, padding=1)

把每 2×2 的区域用 平均值 代替，然后向右/下走 2 步。结果：图像尺寸减半。

输入: [1, 128, 256, 256] │ ▼ AvgPool2d(2, 2, padding=1) │ 输出: [1, 128, 128, 128] 尺寸减半！

为什么需要：尺寸减半后，下一层卷积的 4×4 窗口实际覆盖了原图更大的区域（感受野变大）。这就像从"看纹理细节"过渡到"看零件形状"。

3. 组合起来：PDN Small

现在来看完整的 get_pdn_small（common.py:64-79）：

nn.Sequential(
    # Layer 1: 细节层
    nn.Conv2d(in_channels=3, out_channels=128, kernel_size=4, padding=3),
    nn.ReLU(inplace=True),
    nn.AvgPool2d(kernel_size=2, stride=2, padding=1),     # 256→128

    # Layer 2: 纹理层
    nn.Conv2d(in_channels=128, out_channels=256, kernel_size=4, padding=3),
    nn.ReLU(inplace=True),
    nn.AvgPool2d(kernel_size=2, stride=2, padding=1),     # 128→64

    # Layer 3: 部件层
    nn.Conv2d(in_channels=256, out_channels=256, kernel_size=3, padding=1),
    nn.ReLU(inplace=True),

    # Layer 4: 输出层
    nn.Conv2d(in_channels=256, out_channels=384, kernel_size=4),
)

数据流的尺寸变化：

输入图片 [1, 3, 256, 256] Conv 1 [1, 128, 256, 256] AvgPool 1 [1, 128, 128, 128] Conv 2 [1, 256, 128, 128] AvgPool 2 [1, 256, 64, 64] Conv 3 [1, 256, 64, 64] Conv 4 [1, 384, 61, 61] ← 最终特征图

注意最后一步：kernel_size=4, padding=0（没有 padding），所以尺寸从 64→61（64−4+1=61）。

关键洞察：这个网络的"深度"只有 4 层卷积 — 这就是为什么它叫 小 PDN。中等版本有 6 层。EfficientAD 的设计哲学是"用浅层网络就能做异常检测"。

4. 再看一个：Autoencoder

get_autoencoder（common.py:6-62），前半段类似 PDN，后半段反向放大：

# 编码器（下采样）: 256 → 128 → 64 → 32 → 16 → 1
nn.Conv2d(3→32, kernel=4, stride=2), ReLU    # 256→128
nn.Conv2d(32→32, kernel=4, stride=2), ReLU   # 128→64
nn.Conv2d(32→64, kernel=4, stride=2), ReLU   # 64→32
nn.Conv2d(64→64, kernel=4, stride=2), ReLU   # 32→16
nn.Conv2d(64→64, kernel=4, stride=2), ReLU   # 16→8
nn.Conv2d(64→64, kernel=8)                   # 8→1  (瓶颈!)

# 解码器（上采样）: 1 → 3 → 8 → 15 → 32 → 63 → 127 → 56
nn.Upsample(size=3), Conv2d(64→64), ReLU     # 放大 + 卷积
nn.Upsample(size=8), Conv2d(64→64), ReLU
...

和 PDN 的区别：用 stride=2 代替 AvgPool 来降尺寸；用 Upsample 来恢复尺寸。Autoencoder 的核心思想是 先压缩再重建 — 中间那个 1×1 的瓶颈层迫使网络只保留最关键的信息。

5. 检索练习

Quiz: CNN 直觉

回答以下问题，然后点击查看答案。

1. 为什么 Conv 的输出通道数（比如 128）比输入通道数（比如 3）多很多？

因为输出需要检测 更多种类的视觉模式。输入只有 RGB 三个通道（红、绿、蓝），但输出需要 128 个通道来检测边缘、纹理、角点、颜色梯度等 128 种不同的低级特征。通道数 = 模式种类数。

2. AvgPool(2, 2) 之后，一张 256×256 的特征图变成多大？

128×128。每个 2×2 区域合并成一个值，步长 2 意味着窗口不重叠，所以宽高各除以 2。

3. PDN Small 最后输出是 [1, 384, 61, 61]。这 384 是什么？如果有 batch_size=8，输出形状是什么？

384 是输出通道数，即 384 张特征图，每张 61×61。
batch_size=8 时形状是 [8, 384, 61, 61]。

4. Autoencoder 中间的 bottleneck 层输出 [1, 64, 1, 1] — 这是什么意思？

64 个数字，空间上被压缩到 1×1 像素。这 64 个数字是整个输入图像的 压缩表示（latent code），包含了图像"是什么"的最本质信息。
